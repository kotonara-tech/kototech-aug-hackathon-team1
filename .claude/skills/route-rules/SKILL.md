# ルート生成の決まり

このサービスの存在意義は「**次の予定までに、指定されたゴール地点へ確実に戻れる**寄り道ルート」です。
この条件を緩める変更・削除は、ユーザーが明示的に指示しない限り行いません。

## 1. 必須条件（フィルタ）— 満たさない候補は順位付けの前に捨てる

- `arrivalAtGoal <= requiredEndTime - safetyBuffer`
- `totalExpectedCost <= budget`（1人あたり）
- 到着時刻から滞在終了まで、施設が営業している見込みがある
- 指定した移動方法（徒歩 / 公共交通）で移動できる
- 予約が必要な施設は、予約期限を満たしている

**合計時間には必ず移動時間を含めます。** 滞在時間だけの合計は誤りです。
`safetyBuffer` は必ず正の値を持たせ、0 にしないこと。

## 2. 順位付け（フィルタを通った候補だけ）

1. ユーザーの希望（行きたい店、食べたいもの、地域）との一致
2. SHIKA no ASHIATO 掲載施設か
3. 移動効率
4. 3案どうしの違い
5. 元データの信頼度

## 3. 3案の出し方

- 3案は**実際に内容が違う**こと。同じ施設の並べ替えだけにしない
- 候補が3つに満たないときは、無理に埋めず「候補なし」を正直に表示する
- 予算を超える案を出すなら、超過額を分かる形で警告する

## 4. データの区別を崩さない

画面と説明の両方で、次の4つを混ぜないでください。

| 種別 | 例 | 表示の扱い |
| --- | --- | --- |
| 公式データ | `app/data/ashiato-spots.json` の375件 | 出典を示す |
| 外部から補った データ | 住所、座標、料金 | 項目ごとの出典と確認日時を出す |
| 試算値 | 現在の `routes` / `spots` の固定値 | 「目安・試算」と明示する |
| リアルタイム値 | （現在なし） | 取得元がない限り最新と表示しない |

現在の `app/page.tsx` の `routes`（74行〜）と `spots`（41行〜）は**プロトタイプ用の固定値**です。
実際に取得した最新データとして扱ったり説明したりしないでください。

## 5. 現状（2026-08-21）

- `generate` 関数は `generated` を true にして結果欄を表示するだけで、375件から計算していません
- Google Places API / Routes API / SHIKA no ASHIATO API は未接続
- 地図と Street View は API 呼び出しではなく、施設名・住所・座標から作った外部リンク

実データ接続に進むときは Places / Routes をサーバー側から呼び、キーは用途と実行環境で制限します。
**API キーは絶対にコミットしない**こと。
