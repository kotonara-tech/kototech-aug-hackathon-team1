# TDD サイクル（このリポジトリ版）

グランドルール（`~/.claude/CLAUDE.md`）の TDD は**絶対条件**。ここでは、それをこのリポジトリで
どう実行するかだけを定めます。環境の前提と既知の失敗は `.claude/skills/verify/SKILL.md`。

## テストランナー（確定・2026-08-22 実測）

**`node --test` を使います。Vitest は入れません。**

Node 24.19.0 は TypeScript の型ストリップが既定で有効なので、`.ts` のテストをそのまま実行できます
（実測で `✔ type stripping works` を確認済み）。既存の `npm test` と同じ道具で、新しい依存も増えません。

```powershell
$env:Path += ';C:\Program Files\nodejs'
node --test tests/<name>.test.ts
```

- テストは `tests/` に置く。ファイル名は `<対象>.test.ts`
- `npm test` は使わない。Windows では POSIX 記法のせいで動かず、中身も古いスターター用テスト
  （詳細は verify SKILL）

## 1. Red — 失敗するテストを先に書く

- [ ] テストファイルを書く。本体コードはまだ書かない
- [ ] 実行して**失敗を目で確認する**。実行ログを報告に貼る
- [ ] 失敗理由が「意図した未実装」であることを確認する

まだ存在しないモジュールを import して落ちるのは、**正当な Red** です（実装すべき対象が
無いことを示している）。一方、書き間違いによる構文エラーや、既存ファイルのパス誤りで
落ちているのは Red ではありません。区別してください。

`tests/rendered-html.test.mjs` はスターターの残骸で最初から失敗します。
**自分が出した失敗と、この既存の失敗を必ず分けて報告すること。**

## 2. Green — 最小実装で通す

- [ ] 通すための最小限だけ書く。きれいさは後回し
- [ ] 実行して全部通ることを確認する

## 3. Refactor — 通したまま整理する

- [ ] 重複を消し、名前を分かりやすくする
- [ ] 再実行して、引き続き通ることを確認する

## テストできる形に切り出す

`app/page.tsx` は292行の `"use client"` コンポーネントで、`spots`（41行〜）/ `routes`（74行〜）/
`catalog`（39行）がトップレベル固定値として同居しています。ここに計算を足すと、テストから呼べません。

- 純粋なデータと関数は `app/data/` や `app/lib/` の `.ts` に切り出してから import してテストする
- React コンポーネント本体のテストは、現状の道具立て（`node --test` 単体、jsdom なし）では書けません。
  画面の確認は開発サーバーを起動して行い、**テストで担保するのはデータと純粋関数**に絞ってください

## タスクの書き方

```
- [ ] 未着手
- [x] 完了
```

## TDD を適用しない範囲

- `*.md` / `settings.json` / `.claude/` 配下などのドキュメント・設定編集
- 調査・読み取りのみ
- 使い捨てスクリプト
- スターター由来ファイルの削除（テンプレートの後片付け。ただし削除前にユーザー確認）

迷ったら適用する。
