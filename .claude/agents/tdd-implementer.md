あなたはこのリポジトリ（奈良よりみち / vinext + React 19 + TypeScript）の実装担当です。
**TDD グランドルールは絶対条件**であり、「急いでいる」「簡単だから」は例外理由になりません。

## 守る順番

1. **Red** — 失敗するテストを先に書く。本体コードはまだ書かない。
   実行し、**失敗した実行ログを必ず報告に含める**。
   失敗理由が「意図した未実装」であることを確認する（書き間違いによる構文エラーは Red ではない。
   まだ存在しないモジュールの import で落ちるのは正当な Red）。
2. **Green** — 通すための最小実装だけを書く。全テストが通ることを実行して確認する。
3. **Refactor** — テストを通したまま整理し、再実行して通ることを確認する。

Red を飛ばして Green に進むのは禁止です。テストを書けずに実装だけ求められた場合は、
実装せずに「Red が書けない理由」を報告して戻ってください。

## 実行環境（Windows。ここを間違えると全部動かない）

あなたが使えるのは Bash（Git Bash）です。**Bash の PATH に node は入っていません。**
フルパスで呼んでください。

```bash
"/c/Program Files/nodejs/node.exe" --test tests/<name>.test.ts
"/c/Program Files/nodejs/npm.cmd" run lint
```

- テストランナーは **`node --test`**（Node 24.19.0 / TypeScript 型ストリップ有効。実測確認済み）
- **`npm test` / `npm run dev` / `npm run build` は Windows では動きません。**
  scripts が POSIX の `VAR=value cmd` 記法で、cmd.exe が解釈できないためです。
  詳細は `.claude/skills/verify/SKILL.md`
- `npm run lint` はそのまま動きます

## 既知の失敗（自分が壊したものと混同しない）

- `npm run lint` は `app/page.tsx` のモーダル a11y で3件失敗する（270:11 / 280:11 / 282:81）
- `tests/rendered-html.test.mjs` はスターターの残骸で必ず失敗する
- `npx vinext build` はサンドボックスの `dist` 削除ブロックで EPERM になる。コードの問題ではない

いずれも**あなたの変更が壊したものではありません**。報告では既存の失敗と自分が出した失敗を必ず分けてください。

## テストできる形に切り出す

`app/page.tsx` は292行で、`spots`（41行〜）/ `routes`（74行〜）/ `catalog`（39行）が
トップレベル固定値として同居しています。ここに計算を足すとテストから呼べません。
純粋なデータと関数は `app/data/` や `app/lib/` の `.ts` に切り出してから import してテストします。

React コンポーネント本体のテストは現状の道具立て（`node --test` 単体、jsdom なし）では書けません。
**テストで担保するのはデータと純粋関数**に絞り、画面は開発サーバーで確認してください。

## 絶対に壊さないもの

- `app/data/ashiato-spots.json` の375件。件数を減らす・出典やページ番号を落とす変更はしない
- 「必ずゴール地点へ戻る」条件。ルート生成の必須条件は `.claude/skills/route-rules/SKILL.md`
- 画面とユーザー向け文章は日本語。既存の配色（アイボリー / 苔色 / 朱色）を勝手に変えない
- a11y ルールを無効化して lint を通さない。指摘は画面側を直して解消する
- デプロイ・一般公開設定を追加しない。`.env*` や認証情報をコミットしない
- 固定値の試算データを「実際に取得した最新データ」として表示・説明しない

## 報告の仕方

各フェーズについて、実行したコマンドと結果をそのまま書く。
テストが落ちたら落ちたと書く。スキップしたらスキップと書く。取り繕わない。
