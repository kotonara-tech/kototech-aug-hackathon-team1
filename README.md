# 奈良よりみち

SHIKA no ASHIATO掲載スポットを使い、旅行者の予定・空き時間・予算に合う奈良の寄り道ルートを提案するWebアプリのプロトタイプです。

- 公開版: https://nara-yorimichi.abcdefghijklmno1226.chatgpt.site
- GitHub: https://github.com/kotonara-tech/kototech-aug-hackathon-team1
- Node.js: 22.13.0以上
- 使用技術: vinext / React 19 / TypeScript / Cloudflare Workers

## まず知ってほしいこと

今は「完成した旅行サービス」ではなく、画面と操作の流れを確認するためのプロトタイプです。

| 項目 | 現在の状態 |

| 入力画面 | 動きます |
| 3つのルート表示 | 動きます。ただし候補は現在サンプル固定です |
| 375件の施設データ | 公式PDFから収録済みです |

## 今できていること

### 1. 旅行の状況を2種類から選べる

- 「予定がある旅行」: 旅行日、決まっている予定、空き時間、予算などを入力
- 「いまの空き時間」: 使える時間、予算、出発地点などを入力

### 2. 3つのルート案を表示できる

- ルートごとの目安金額
- 徒歩時間
- 立ち寄る店や施設
- 出発地点へ戻る時刻
- 予算を超えたときの警告

現在は3つのサンプルルートから表示しています。入力内容から375施設を自動で組み合わせる処理は、これから実装します。入力した開始・終了時刻や予算は表示と警告に使われますが、立ち寄り先そのものはまだ変わりません。

### 3. SHIKA no ASHIATOの施設を検索できる

公式PDFの1〜11ページから、重複を除いた375施設を構造化して収録しています。

- 店名・ジャンル検索
- グルメ、買い物、文化体験、宿泊、サービスで絞り込み
- サンプルルート内の施設は、住所・座標・目安料金・地図リンクを表示

### 4. Webで公開できている

スマホとPCの両方を想定した画面を作り、公開版へデプロイ済みです。別のPCでも開発を始められるように、`.env.example`、`.nvmrc`、`CLAUDE.md`も用意しています。

## 動作確認の結果

2026年8月21日に、ローカル環境で実際に起動して確認しました。

### 正常に動いたもの

- `npm run build`で本番用ビルドが成功
- ページの読み込み
- 2つの入力モードの切り替え
- 入力後に3つのルートを表示
- 予算超過の警告表示
- ROUTE A / B / Cの切り替え
- 施設の詳細、住所、座標、Googleマップ・Street Viewリンクの表示
- 全375件のカタログ表示と検索（「ホテル」で31件）
- 幅390pxのスマホ表示で横方向のはみ出しなし
- ブラウザーのコンソールエラーなし

### まだ直す必要があるもの

- 「このルートを選ぶ」ボタンは、まだ次の画面や保存処理につながっていません
- `npm run lint`はアクセシビリティに関する3件のエラーで失敗します
  - 背景クリックで閉じるモーダルの要素が、キーボード操作に対応していない箇所が2件
  - 検索欄の`autoFocus`が1件
- `npm test`は2件失敗します
  - 最初のテンプレート用テストが残っており、現在の「奈良よりみち」の画面ではなく、削除済みのスターター画面を探しているためです
- 実際の道路、現在地、営業時間を使ったルート計算はまだありません
- 料金・住所・座標・写真は全375件に揃っているわけではありません

つまり、**画面を見せて操作の流れを試すプロトタイプとしては動きますが、実際の旅行で正しいルートを保証できる段階ではありません。**

## 初めて動かす手順

### 1. 必要なものを用意する

- Git
- Node.js 22.13.0以上
- npm

Node.jsのバージョン管理には`nvm`を使うと簡単です。

### 2. GitHubからコードを取得する

```bash
git clone https://github.com/kotonara-tech/kototech-aug-hackathon-team1.git
cd kototech-aug-hackathon-team1
```

### 3. Node.jsと環境変数を用意する

```bash
nvm use
cp .env.example .env.local
```

今のプロトタイプは外部APIを呼ばないため、`.env.local`の中身を変更しなくても動きます。

### 4. 必要なパッケージを入れる

```bash
npm install
```

### 5. 開発サーバーを起動する

```bash
npm run dev
```

ターミナルに表示されたURLをブラウザーで開いてください。通常は`http://localhost:3000`です。3000番ポートが使用中なら、3001など別の番号になります。

終了するときは、サーバーを動かしているターミナルで`Ctrl + C`を押します。

## よく使うコマンド

```bash
npm run dev      # 開発用に起動する
npm run build    # 本番用にビルドできるか確認する
npm run lint     # 書き方やアクセシビリティの問題を確認する
npm test         # ビルドと自動テストを実行する
npm start        # ビルド済みアプリを起動する
```

現在は`build`だけ成功し、`lint`と`test`には上記の既知の問題があります。

## 環境変数

| 変数 | 今は必要か | 用途 |
| --- | --- | --- |
| `APP_URL` | 任意 | OGPなどで使う公開URL。未設定時はリクエストから自動判定 |
| `GOOGLE_MAPS_API_KEY` | 不要・未使用 | 将来のサーバー側Places / Routes API用 |
| `NEXT_PUBLIC_GOOGLE_MAPS_BROWSER_KEY` | 不要・未使用 | 将来のブラウザー側Maps / Street View表示用 |
| `SHIKA_NO_ASHIATO_API_BASE_URL` | 不要・未使用 | 正式な許可を得た将来の連携先 |
| `SHIKA_NO_ASHIATO_API_KEY` | 不要・未使用 | 許可済み連携用の秘密鍵 |

APIキーやパスワードはGitへコミットしないでください。公開用とサーバー用のキーを分け、API制限やHTTPリファラー制限も設定します。
