# 奈良よりみち

SHIKA no ASHIATO掲載スポットを使い、旅行者の予定・空き時間・予算に合う奈良の寄り道ルートを提案するWebアプリのプロトタイプです。

- GitHub: https://github.com/kotonara-tech/kototech-aug-hackathon-team1
- 実行方法: ローカル環境のみ（一般公開しない）
- Node.js: 22.13.0以上
- 使用技術: vinext / React 19 / TypeScript / Cloudflare Workers

## 今できていること

### 1. 旅行の状況を2種類から選べる

- 「予定がある旅行」: 旅行日、決まっている予定、空き時間、予算などを入力
- 「いまの空き時間」: 使える時間、予算、出発地点などを入力

### 2. 3つのルート案を表示できる

- ルートごとの目安金額
- 徒歩時間
- 立ち寄る店や施設
- 出発地点へ戻る時刻
- 予算を超えたときの警告

現在は3つのサンプルルートから表示しています。入力内容から375施設を自動で組み合わせる処理は、これから実装します。入力した開始・終了時刻や予算は表示と警告に使われますが、立ち寄り先そのものはまだ変わりません。

### 3. SHIKA no ASHIATOの施設を検索できる

公式PDFの1〜11ページから、重複を除いた375施設を構造化して収録しています。

- 店名・ジャンル検索
- グルメ、買い物、文化体験、宿泊、サービスで絞り込み
- サンプルルート内の施設は、住所・座標・目安料金・地図リンクを表示

### 4. ローカル環境で起動できる

スマホとPCの両方を想定した画面です。別のPCでも開発を始められるように、`.env.example`、`.nvmrc`、`CLAUDE.md`を用意しています。一般公開用のホスティング設定は削除しており、`npm run dev`でローカル起動して使います。

## このプロダクトが動く仕組み

### 全体の流れ

```text
npm run dev
  ↓
Viteとvinextがローカルサーバーを起動
  ↓
app/layout.tsxがページ全体の情報とCSSを読み込む
  ↓
app/page.tsxが画面と操作を作る
  ├─ app/data/ashiato-spots.jsonから375施設を読み込む
  ├─ app/page.tsx内の固定サンプル3ルートを読み込む
  └─ ユーザーの入力をブラウザーのメモリに保持する
  ↓
「3つのルートをつくる」を押すとサンプル3案を表示
```

### どこから何を読み込んでいるか

| 読み込み元 | 読み込む内容 | 使う場所 |
| --- | --- | --- |
| `app/data/ashiato-spots.json` | 施設名、カテゴリ、ジャンル、ならふる対応、PDF掲載ページの375件 | 全件カタログの件数、検索、カテゴリ絞り込み |
| `app/lib/places.ts` | ルート候補6件の住所、座標、目安料金、滞在時間、写真URL、説明 | ルート計算、ルート詳細、施設詳細モーダル |
| OpenStreetMap（Nominatim） | 知らない地名の座標 | 出発地・ゴールの位置決め |
| OpenStreetMap（OSRM 徒歩） | 地点どうしの実際の徒歩時間 | ルートの所要時間と、時間内に戻れるかの判定 |
| `app/globals.css` | 色、文字、配置、スマホ表示 | 画面全体の見た目 |
| `app/layout.tsx` | ページタイトル、説明、OGP画像URL | ブラウザーのタイトルとページ情報 |
| `public/og.png`、`public/favicon.svg` | ページ画像とアイコン | ブラウザーやSNS向けの表示 |

375施設の元データは奈良市公式PDFです。ただし、アプリを開くたびにPDFを読み直しているわけではありません。PDFから事前に抽出した結果を`app/data/ashiato-spots.json`へ保存し、起動時にそのローカルファイルを読み込んでいます。

375件には住所・座標・料金・滞在時間が入っていないため、ルート計算にはまだ使えません。計算に使えるのは`app/lib/places.ts`の6件だけです。

### OpenStreetMapの使い方と制限

徒歩時間と地名検索には、OpenStreetMapの公開サービスを使っています。無料でAPIキーも不要ですが、**ボランティアが運営する共有サーバー**です。次を守っています。

- 1回のルート生成につき、外部への通信は最大3回（地名検索2回＋徒歩時間1回）
- 徒歩時間は区間ごとではなく、総当たり表として1回でまとめて取得
- 知っている地名（近鉄奈良駅など7か所）は問い合わせない
- 同じ問い合わせの結果は覚えておき、2回目以降は通信しない
- 利用規約どおり`User-Agent`で名乗る

実測では、徒歩時間の応答は1〜11秒とばらつきます。応答が返らない場合は直線距離からの概算へ自動で切り替え、画面に「概算です」と表示します。**本番で公開するなら、自前のサーバーを立てるか有料サービスへ移す必要があります。**

### ユーザーが入力した後の処理

1. 入力した日程、予算、出発地などをReactの`useState`でブラウザーのメモリに保存します。
2. 「3つのルートをつくる」を押すと、`/api/routes`へ入力内容を送ります。
3. サーバー側で、知らない地名の座標をOpenStreetMapに問い合わせます。
4. 地点どうしの実際の徒歩時間を、OpenStreetMapから総当たり表で取得します。
5. 予算内で、余裕を残してゴールへ戻れる組み合わせだけを残し、点数を付けて上位3案を選びます。
6. 結果を時計表示に直して画面へ返します。読み込み中・候補なし・エラーはそれぞれ別の表示になります。
7. カタログ検索では`useMemo`を使い、名前・カテゴリ・ジャンルをブラウザー内で絞り込みます。最初は30件だけ表示し、「さらに30件表示」で追加します。

入力前に見えている「提案イメージ」だけは、通信せずに直線距離の概算で計算しています。ボタンを押すと実際の徒歩時間で計算し直します。

### 今は読み込んでいないもの

- Google Places APIやRoutes APIは呼び出していません
- SHIKA no ASHIATOのアプリAPIは呼び出していません
- データベースは使っていません
- ログイン処理は使っていません
- 入力内容や選んだルートを`localStorage`などへ保存していません。ページを再読み込みすると初期値へ戻ります

施設の写真は外部サイトの画像URLをブラウザーから読み込みます。また、GoogleマップとStreet Viewは外部ページへのリンクです。徒歩時間と地名検索もOpenStreetMapへの通信を伴います。そのため、アプリ本体はローカル起動でも、インターネット接続が必要です。

### 優先2: 本当に入力内容からルートを作る

画面の入力から実際にルートを計算するようになりました。固定の3ルートは削除しています。

処理の流れは次のとおりです。

1. `app/lib/route-request.ts`が、画面の文字入力（「2時間30分」「3,000円」など）を分と円の数値へ変換する
2. `app/lib/osm.ts`が、知らない地名の座標と、地点どうしの実際の徒歩時間をOpenStreetMapから取得する
3. `app/lib/route-engine.ts`が、条件を満たすルートを最大3つ組み立てる
4. `app/lib/route-view.ts`が、結果を画面表示用（時計表示、「徒歩10分」など）へ変換する
5. `app/api/routes/route.ts`が、この一連の処理をPOSTの窓口として公開する
6. `app/page.tsx`が、送信時に`/api/routes`を呼んで結果を表示する

計算をサーバー側に置いたのは、外部サービスへの問い合わせ回数をここで抑えるためです。将来Google Maps PlatformなどのAPIキーを使うようになっても、キーをブラウザーへ出さずに済みます。

必ず守る条件は次の2つです。

- 安全余裕（既定10分）を残して、指定されたゴール地点へ戻れること
- 立ち寄り先の合計金額が予算以内であること

満たしたうえで、備考のキーワード一致、SHIKA no ASHIATO掲載、立ち寄り数、移動効率で点数を付け、内容の重ならない3案を選びます。

徒歩時間はOpenStreetMapの徒歩ルートから取得した実際の所要時間です。外部サービスへ接続できないときだけ、直線距離からの概算（分速80m）へ切り替わります。ただし、座標・料金・滞在時間が揃っている施設が`app/lib/places.ts`の6件しかないため、ルートに出てくるのはこの6件だけです。

## 初めて動かす手順

### 1. 必要なものを用意する

- Git
- Node.js 22.13.0以上
- npm

Node.jsのバージョン管理には`nvm`を使うと簡単です。

### 2. GitHubからコードを取得する

```bash
git clone https://github.com/kotonara-tech/kototech-aug-hackathon-team1.git
cd kototech-aug-hackathon-team1
```

### 3. Node.jsと環境変数を用意する

```bash
nvm use
cp .env.example .env.local
```

今のプロトタイプは外部APIを呼ばないため、`.env.local`の中身を変更しなくても動きます。

### 4. 必要なパッケージを入れる

```bash
npm install
```

### 5. 開発サーバーを起動する

```bash
npm run dev
```

ターミナルに表示されたURLをブラウザーで開いてください。通常は`http://localhost:3000`です。3000番ポートが使用中なら、3001など別の番号になります。

終了するときは、サーバーを動かしているターミナルで`Ctrl + C`を押します。

## よく使うコマンド

```bash
npm run dev      # 開発用に起動する
npm run build    # 本番用にビルドできるか確認する
npm run lint     # 書き方やアクセシビリティの問題を確認する
npm test         # ビルドと自動テストを実行する
npm start        # ビルド済みアプリを起動する
```

現在は`build`だけ成功し、`lint`と`test`には上記の既知の問題があります。
